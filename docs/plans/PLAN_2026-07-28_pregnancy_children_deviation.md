# 妊娠・出産・子キャラ登場／ユーザー指示の逸脱抑制　設計と実装計画

2026-07-28 時点の設計確定内容。**未実装**。

---

## 0. 設計を左右した実測値

実プレイDBは 6073 メッセージで `current_day` = 52（≒120メッセージで1日）。
現実準拠の 280 日妊娠も、子が会話可能になる年齢も、逐次プレイでは絶対に到達しない。

よって設計目標は「時間を短縮する」ではなく、**時間跳躍を一級の機能にするか、飛ばさずに済ませるか**を
World 作者に選ばせることに置く。

跳躍そのものは今の作りだとほぼタダである。季節・曜日・休日・妊娠しやすさ周期はすべて
`current_day` からの導出で可変状態を持たないため、`current_day` を大きく進めても辻褄が自動で合う。
壊れるのは「日付から導出していないもの」＝キャラの年齢・外見・部屋の顔ぶれ・関係の履歴だけ。

## 1. 妊娠・出産・子

### 1.1 データ

`character_pregnancies`（ルート単位・モブ対象外）1テーブルで受胎→出産→登場まで通す。

| 列 | 意味 |
|---|---|
| `playthrough_id` / `character_id` | どのルートの誰が |
| `partner` | 誰との子か。**当面「あなた」のみ受付**（列は他キャラも取れる形で持つ） |
| `conceived_day` | 受胎日。妊娠段階はここからの差分で導出 |
| `known_from_day` | 本人が妊娠を知った日（NULL＝未発覚） |
| `ended_day` / `outcome` | 出産・流産・中絶。出産なら以後これが「誕生日」 |
| `child_name` / `child_gender` | 出産時に決まる。キャラ化前でも会話で名前を呼べる |
| `child_character_id` | キャラ化されたら埋まる（NULL＝まだ登場していない） |

**妊娠段階も成育段階も `current_day` からの差分で毎回導出する。**
保存するのは日付だけ（周期・季節・曜日と同じ設計思想）。日付が後から変わってもズレようがない。

### 1.2 World設定（2軸）

| 設定 | 値 | 現代ファンタジー(World4) |
|---|---|---|
| 軸A キャラの加齢 | `静止`（サザエさん空間） / `通常`（n年後跳躍を許可） | 通常 |
| 軸B 子の登場 | `登場しない` / `跳躍時に登場` / `早熟` | 早熟 |
| 成育日数 | 日数（早熟時） | 30日（テストルートでは短縮） |
| 登場時の年齢 | 下限・上限 | 就学前（4〜6） |
| 妊娠期間 | 日数 | 周期長×3程度 |
| 出産と成長の理 | 自由文 | 「揺り籠」の説明 |

- 3択ではなく2軸にしたのは、**サザエさん空間＋早熟**（時間は止まっているが子は登場する）が
  組み合わせとして成立し、3択では作れないため。
- 登場時の年齢の実効値は `clamp(下限, 上限)` **かつ母の `age_real` 未満**。
  母の `age_real` が空ならWorld上限にフォールバック。
  あなたには年齢の項目が無い（`protagonist_*` は名前・呼称・職業・外見・性別・備考のみ）ため、
  判定は母の年齢だけで行う。
- 「出産と成長の理」は `worldview` 本文とは別欄にし、**妊娠・出産・子が絡む場面でだけ**注入する。
  大多数のセッションで無駄に載せないため。

> **注意**：軸Aの `通常` は当面**挙動差ゼロ**。`age_real` は静的な列で日々の加齢は未実装であり、
> 加齢は跳躍時にまとめて加算すれば足りる。**日々の加齢を作り込まないこと。**

### 1.3 確定した判断

- **父は「あなた」限定**。`playthroughs.protagonist_mode = 'narrator'`（神・ナレーター視点）の
  ルートでは機能ごと無効化する。ナレーター視点には父になる「あなた」が存在しないため。
  既存3ルートはすべて `character` なので影響なし。
- **子はルート固有＝自動作成キャラ**として作られ、その後は通常のキャラ編集画面で手直しする。
  専用ウィザードは作らない。
- **キャラ行の作成と立ち絵生成は分ける**。koboldcpp 停止中でも行は必ず作られ、画像は
  既存の生成ボタンで後から作れる。
- **エクスポート**：個別（`GET /characters/:id/export-bundle`、既存）は除外しない
  （デバッグ・キャラ流用のため）。世界観エクスポート（`contentBundle.js`）からは除外する。

### 1.4 現代ファンタジーの世界観整合：「揺り籠」

生まれた子は一度「向こう側」に預けられ、しばらくして育った姿で戻ってくる。誰もが通る当たり前の習わし。

採用理由は**繰り返しテストへの耐性**：

- 出産と登場を切り離せる（産んだ直後の育児描写を書かずに済み、`成育日数` がそのまま演出になる）
- 何度起きても違和感がない（「魔力による急成長」「世界の理」だと奇跡が安売りされる）
- 既存の World4 コンテンツを1行も壊さない（既存の家族キャラも同じ道を通ったことにできる）
- 主人公が疑問に思わない理由が要らない（全員が通る当たり前のことなので誰も説明しない）

整合を守るガード：**到達年齢を就学前に止める**（在学・学籍の話を発生させない）、
**急成長は新生児のみ**（既存キャラは軸Aに従う）、**到達後は通常の速度**。

### 1.5 プロンプトへの出方（本人が知っている範囲でのみ）

| 段階 | LLMに渡すもの |
|---|---|
| 未発覚 | 何も渡さない（体調変化だけ匂わせる） |
| 発覚後〜出産 | 「妊娠n週目、相手はあなた」 |
| 揺り籠中 | 「子（名前）を預けている。戻るのは当分先」 |
| 登場後 | 通常の参加者。特別扱い不要 |

発覚はイベント（検査・保健室・相手からの指摘）で `known_from_day` が入って初めて本人の知識になる。
拾えるアイテムを「発見して初めてリストに出る」ようにしたのと同じ考え方。

### 1.6 記憶との相性（実装不要）

改変も揺り籠も「誰も不思議に思わない」設定なので、`character_memories` には
**歪んだ後の世界が普通の過去として**積まれる。ここは何も作らなくても整合する。

### 1.7 実装で一番重い箇所：ルート固有キャラの波及点

1. キャラ一覧の World 所属導出**3経路すべて**（明示アタッチ／部屋スロット／属性タグ）にルート絞り込み
2. World 複製・`contentBundle` エクスポートから除外
3. ルート削除時に連鎖削除（立ち絵も）
4. プリセットのイベント定義が掴まないこと
5. 個別 `export-bundle` は除外しない

ここを詰めずに実装すると「ハーレムルートの子が純愛ルートに出る」類の破綻を追うことになる。

## 2. ユーザー指示の逸脱抑制

発端は、主人公＝あなたに**無自覚な世界改変能力**があるという設定を現代ファンタジーに足したいという要望。
LLM 主体のゲームで無茶な指定が通ってしまうことの、世界観的な裏付けを兼ねる。

> **警告**：この設定を単体でプロンプトに載せると追従が**悪化する**。
> LLM は「設定上そういうものだから」と読んで、今より無茶を通すようになる。
> 入れるなら制限を同時に書くこと。

### 2.1 3軸

| 軸 | 値 | 効かせ方 |
|---|---|---|
| 軸1 改変対象（複数選択） | `世界法則・設定` / `状況・物理` / `他者の心` | プロンプト＋機構 |
| 軸2 逸脱時の扱い | `受容` / `読み替え` / `押し返し` | プロンプトのみ |
| 軸3 方針の提示 | `なし` / `ルート開始時に宣言文` | UIのみ・LLM不使用 |

- 軸1を段階スケールではなく**チェックボックスの集合**にしたのは、ギャルゲ版の要求が
  「心だけ外す」＝強度ではなく**対象**の問題で、1本のスケールでは表現できないため。
- 軸2は**列だけ作って既定 `受容`（＝現状の挙動）**とし、プロンプト文の作り込みは後回し。
  現代ファンタジーもギャルゲ版も `受容` で、今は検証対象が無いため。
- 軸3は「無茶はユーザーの良心に任せるが推奨しない」の置き場所。
  毎ターン逸脱判定をするとローカル LLM でレイテンシが倍になるので、**開始時一度きりの宣言**にした。
  判定が要る場面は既存の `llm_judge` 条件を持つイベントを World 作者が書く。

### 2.2 関係値の1回あたり変動上限（軸1とは独立の設定）

`relationshipAutoUpdate.js` の定期関係値更新は、LLM が返した増減値を**上限チェックなしで
そのまま加算している**（`parseInt` → `adjustValue(..., 'add', delta)`）。
`好感度|+100` と返れば一発で100上がる。「心は歪まない」をプロンプト文だけで書いても、
LLM がユーザーの無茶に引っ張られた瞬間に機構側が素通しする。

上限は軸1の「他者の心」とは**独立した設定**にする（心の改変を許す World でも事故の暴走だけ防げるように）。
値は短編前提か長期前提かで変わるため World 側で調整する。

### 2.3 World別の設定値

| | 現代ファンタジー | ギャルゲ版（派生予定） |
|---|---|---|
| 軸1 世界法則・設定 | ✓ | ✓ |
| 軸1 状況・物理 | ✓ | ✓ |
| 軸1 他者の心 | ✓ | **✗** |
| 関係値の変動上限 | なし | あり |
| 軸2 逸脱時の扱い | 受容 | 受容 |
| 軸3 方針の提示 | なし | 宣言文あり |
| 改変能力の設定文 | 「無自覚な世界改変能力」 | 記載しない |

現代ファンタジーは**全部✓＋上限なし＝今の挙動と完全に同一**。テストサンドボックス兼用のため完全フリー。
既定値をこの列に合わせておけば既存 World は何も変わらない。

World 複製は値のコピーなので、派生後に親 World を触っても伝播しない（この使い分けではむしろ正しい）。

## 3. 実装計画

マイグレーションは 0075 から。

| # | 内容 | 規模 | 単体で成立 |
|---|---|---|---|
| P0 | 関係値の変動上限（World設定・独立） | 小 | ○ |
| P1 | 妊娠テーブル＋導出サービス＋フラグミラー | 中 | — |
| P2 | `conceive` / `end_pregnancy` アクション | 中 | — |
| P3 | プロンプト行＋デバッグ欄 | 小 | **○ ここで妊娠が遊べる** |
| P4 | World設定2軸＋成長パラメータ | 小 | — |
| P5 | 成育段階の導出＋登場通知 | 小 | **○ ここで出産まで一周する** |
| P6 | 自動作成キャラの区分と波及点 | **中〜大** | — |
| P7 | 子キャラの自動作成（親から引き継ぎ） | 中 | ○ |
| P8 | 逸脱抑制3軸 | 中 | ○（独立トラック） |

### 各段階の内容

- **P0**（migration 0075）：`worlds.relationship_delta_cap`（NULL＝無制限）。
  `relationshipAutoUpdate.js` で delta を ±cap にクランプ。`STAT_CHANGE` 側も同様に検討。
  既定 NULL で現状の挙動は不変。
- **P1**（migration 0076）：`character_pregnancies` ＋ `worlds.gestation_days`。
  `pregnancy.js` で妊娠段階を導出（`fertilityCycle.js` と同型）。
  **妊娠中は周期段階を「妊娠中」に差し替える**（必須の辻褄合わせ）。
  `character_flags` へ `妊娠段階` をミラー（`season`/`day_of_week` と同じ2箇所：ルート作成時・`advanceTime` 時）。
  → 新しい条件タイプは不要。既存の `flag_state` で作者が分岐イベントを書ける。
- **P2**：`conceive` は現在の周期段階を確率に変換して受胎判定
  （最危険50 / 危険35 / やや危険20 / やや安全8 / 安全2、World 倍率で調整、周期OFFなら固定値）。
  避妊は既存の `has_status` / `has_item` 条件で作者が弾く（機能側に持ち込まない）。
  `end_pregnancy` は `outcome` ＋ `child_name` / `child_gender`。`EventsPage.jsx` に両アクションのUI。
- **P3**：`promptBuilder.js` に段階別の行。既存の周期デバッグ欄に妊娠・成育の行を追加。
- **P4**（migration 0077）：軸A・軸B・成育日数・登場時年齢の上下限・出産と成長の理。`WorldsPage` にUI。
- **P5**：`ended_day` から成育段階を導出（P1の仕組みを再利用）。`ChatPage` に登場通知。
- **P6**（migration 0078）：`characters.origin_playthrough_id`。1.7 の波及点をすべて潰す。
- **P7**：登場可能時に子を自動作成。母から外見・関係初期値・呼称・印象デフォルト・
  母の部屋への同居を引き継ぐ。年齢クランプは 1.2 の規則。
- **P8**（migration 0079）：`worlds` に軸1〜3。既定値は現代ファンタジー列。

### 順序の考え方

**P0を最初に単独で入れる。** 抑制仕様の一部でありながら既存の穴を塞ぐ実バグ修正でもあり、
他のどれとも依存関係がない。既定 NULL なら挙動不変なので単独でコミットして終われる。

次に **P1→P3 で一区切り**（受胎し、気づき、出産まで進む）。
**P4→P5 でさらに一区切り**（揺り籠から戻る頃合いの通知まで一周）。

**P6が本体**。ここだけ性質が違い、既存のキャラ所属導出・エクスポート・ルート削除に手を入れる。
**P5まで動かして妊娠・出産が実際に面白いか確かめてから入る。**

P8は完全に独立。どのタイミングにも差し込める（ギャルゲ版 World 作成の直前でもよい）。

### 検証方針

- **P0**：`+100` を返す状況を作って cap でクランプされること、NULL なら従来どおり通ること
- **P1〜P3**：周期段階を固定したルートで受胎確率を統計的に確認。
  未発覚中はプロンプトに妊娠が一切出ないこと。`narrator` モードのルートで無効化されること
- **P4〜P5**：`成育日数` を3日に縮めたテストルートで、出産→登場通知までを実時間で通す
- **P6**：2ルートを並行させ、片方の子がもう片方のキャラ一覧・イベント・World エクスポートに
  一切現れないこと。個別 `export-bundle` は通ること。ルート削除で連鎖削除されること
- **P7**：母の `age_real` が空のケースを含めて年齢クランプを確認。
  koboldcpp 停止中でもキャラ行が作られること
- 各段階でスクラッチデータを片付け、ベースライン（ルート3件・セッション11件・FKクリーン）に
  戻してからコミットする

## 5. 実装未定メモ：子を次代の主人公にする

2026-08-01 追記。**未設計・未実装。**着想のみを記録する。

> **着手時期：だいぶ後。少なくとも v1.0 相当の機能が揃ってから。**
> 記録時点は v0.1.4。当面は着想の置き場所であって、順番待ちの列に並べない。
> 主人公の持ち方そのもの（`protagonist_*` の平坦な列 → キャラ行）に手を入れる話なので、
> 土台の機能セットが固まる前に着手すると作り直しになる。

生まれた子に「あなた」の座を引き継がせ、世代を跨いで続ける遊び方。
`time_skip` と加齢（軸A `通常`）が既に入っているので、素材は揃いつつある。

### 前提となる制約

- **交代が成立するのは、その子が成人相当の年齢に達してからに限る。**
  子の登場年齢は World 設定の下限・上限（現状 4〜6）でクランプされるため、
  登場直後の子は交代対象にならない。`age_real` が成人に達しているかを
  交代の可否判定に必ず挟むこと。恋愛・妊娠まわりの機構が未成年のキャラに
  対して到達可能にならないよう、ここは設定値ではなくコード側で閉じる。
- 交代後も**親世代のキャラ・関係値・記憶は残す**。世代物の値打ちは
  「親の代の因縁が子の代に効く」ところにあり、リセットすると別ルートと変わらない。

### 男性の子について

「男性の子も作れるようにする必要がある」と考えていたが、**データ上は既に作れる**。

- `child_gender` は「妊娠の発覚・終了」アクションの自由入力がそのまま入るだけで、
  性別で分岐する処理は無い（`childCharacter.js` の `materializeChild`）
- `ママ/パパ` の呼称は**あなたの性別**から決まる（`callUserAsFor`）。子の性別は無関係
- 外見の継承は `race` / `attribute` / `eye_description` / `hair_description` のみ。性別に依存しない
- 関係値の初期値（`CHILD_RELATIONSHIP_DEFAULTS`）も性別で変わらない

直すとすれば**表示だけ**：
- `EventsPage.jsx` の「子の性別」欄のプレースホルダが `例：女児` 固定
- `CharactersPage.jsx` の `emptyForm.gender` が `'女性'` 既定（新規作成フォームの初期値）

### 本当の障壁

交代そのものより、**主人公側にキャラ行が無い**ことが効く。

- `protagonist_*` は `worlds` / `playthroughs` の平坦な列（名前・呼称・職業・外見・性別・備考）で、
  年齢すら持たない（1.2 参照）。交代とは「キャラ行の内容をこの列群へ移す」操作になる
- 移した後、**元の子キャラ行をどうするか**が未決。消すと親の記憶に出てくる名前が浮き、
  残すと「あなた」と同名のキャラが同席しうる
- 次代が女性の場合、その子自身の妊娠は「プレイヤー側の妊娠」（対象外の項）に当たる。
  男性なら既存の父＝あなたの経路がそのまま使えるので、**男女で必要な実装量が非対称**

### 最低限の実装単位（案）

1. `playthroughs` に `protagonist_character_id`（NULL＝従来の平坦な列を使う）
2. 交代アクション or 管理画面のボタン。成人判定と確認を挟む
3. `promptBuilder` の「あなた」構築を、列群とキャラ行の両対応にする
4. 親世代を NPC として残す（`origin_playthrough_id` の子キャラをそのまま使う）
